# ADR log
ADR-001: Android first, Expo + TS. Rationale: founder's React background, quick iteration and native access via development builds.
ADR-002: Offline SQLite source of truth at MVP; no mandatory account. Rationale: immediate safe food logging.
ADR-003: Strictly separate deterministic numeric nutrition domain from LLM. Rationale: correctness and predictable latency/cost.
ADR-004: Cloud agents work on PRs only; humans approve merges and production actions. Rationale: minimize surprise/security risk.
ADR-005: Product name Momentum is provisional until brand/Play name validation. **Superseded by ADR-010 / Phase 0:** installable product name is **nf-fit** (git remote may remain `momentum`).
ADR-010: **nf-fit branding + Android home-screen widgets in scope.** Display name / Expo slug `nf-fit`; Android applicationId `app.nffit.dogfood` (reinstall for existing dogfood builds). Widgets are a product requirement: research in Phase 0 (`docs/13-WIDGETS-SCAFFOLD.md`); ship after real Today metrics exist. Prefer Expo config plugin + native `AppWidgetProvider` (or validated `react-native-android-widget`); Expo Go cannot prove widgets. Widget payloads must preserve `null` for unknown nutrients — never coerce to 0.
ADR-006: No direct public sharing of personal health data and no ads in v0.1.
ADR-007: Smart Recipe Import — local text→draft first; AI/cloud only later with explicit consent. Rationale: cut manual entry friction without inventing nutrition or shipping secrets in APK. See `docs/19-SMART-RECIPE-IMPORT.md`.
ADR-008: Momentum Food Planner — local domain-first module under Food → «План» (not a 6th root tab). Eat Now / weekly drafts / pantry / shopping / budget use deterministic TypeScript for macros, portions, aggregation, and cost; AI only for free-text intent, substitutions, and explanations as editable drafts. Store live prices deferred; v1 = user/receipt prices with dated source labels («оценка по прошлым покупкам», never fake «цена сегодня»). Planned meals never auto-log to diary. Remaining KBJU is guidance, not a food ban. PostgreSQL sync later via separate ADR; SQLite remains offline source of truth for Planner v1. See `docs/20-FOOD-PLANNER-PRD.md`, `docs/21-FOOD-PLANNER-UX.md`, `docs/22-FOOD-PLANNER-DATA.md`. Issues labeled `food-planner` ship **without** `agent-ready` until founder approval.
ADR-009: Purchases / purchase_lines / confirm-before-pantry — snapshot **v14**. See `docs/food-intelligence/05-ADR-PURCHASES.md`. Accepted 2026-10-21. Unconfirmed cart never writes pantry; unknown ≠ 0. Catalog enrichment: OFF + Open Prices + user receipts only; retailer scrape blocked (`docs/food-intelligence/04-SOURCES.md`). Cloud OCR still needs consent UX + spend approval.
ADR-011: **Strength module inside Movement (not a 6th tab).** Snapshot **v19** adds Exercise / WorkoutTemplate(+exercises) / PlannedActivity / WorkoutSession / WorkoutSet. Template ≠ logged session; moving a planned card never rewrites completed history; no automatic food-kcal offset from strength; no shame streak for rescheduling. Ship in stages: (1) constructor + set log + crash-safe draft, (2) week board with move/copy menu then optional drag, (3) strength progress charts, (4) calendar sync only with a later ADR. Seed RU templates «Верх A/B/C», «Ноги + пресс» for dogfood. See `docs/23-STRENGTH-MODULE.md`.
Open: product localization RU/EN? Monetization? Backend provider? Data backup scheme? Feature scope for initial closed test? Support email/legal entity? Confirm after testing. Confirm AI provider + accounts before cloud recipe import. OCR consent before FI photo path.
