# Smart Recipe Import

Цель: вставил большой текст (или позже фото) → черновик рецепта → правка → явное сохранение. Не сидеть вручную перенося КБЖУ из чата.

## Границы (обязательные)

| Правило | Смысл |
|--------|--------|
| Предложение ≠ сохранение | В дневник/библиотеку только после «Сохранить» |
| `unknown ≠ 0` | Нераспознанные граммы и КБЖУ остаются пустыми / `null`, не нулями |
| Нет выдуманных нутриентов | Локальный парсер не угадывает БЖУ; AI (позже) тоже только draft + Zod |
| Offline-first MVP | Текст → структура на устройстве, без сети и без аккаунта |
| Согласие на облако | Фото/текст на сервер — только после явного согласия и ADR на backend |

## Фазы

### Phase 0 — сейчас (локальный прототип)

1. Пользователь вставляет текст рецепта.
2. Детерминированный парсер (`parseRecipeText`) извлекает название, выход, строки ингредиентов, инструкции.
3. Открывается обычный редактор рецепта с предзаполнением.
4. Пользователь правит граммы/КБЖУ и сохраняет через существующий `createRecipe`.

### Phase 1 — (не начато) каталог / OFF

Сопоставление имён ингредиентов с локальным каталогом и кэшем OFF → заполнение per-100g только из известных источников.

### Phase 2 — (не начато, нужен backend)

`POST /v1/ai/recipe-import`: согласие → `ai_job` → структурированный draft → валидация → UI confirm. Ключи AI только на сервере. См. обсуждение hybrid architecture; sync/accounts — отдельные ADR.

## UX

- Точка входа: Рецепты → «Из текста» (и кнопка на экране нового рецепта).
- Копирайт нейтральный: «Черновик из текста — проверь граммы и КБЖУ».
- Без shame / без «AI угадал идеально».

## Тесты приёмки Phase 0

- [ ] Пустой текст → понятная ошибка, ничего не сохраняется.
- [ ] Текст с «200 г курицы» → ингредиент с граммами; КБЖУ пустые.
- [ ] Строка без грамм → имя есть, граммы пустые (не 0).
- [ ] После импорта сохранение идёт только по кнопке редактора.
- [ ] `npm test` покрывает парсер; typecheck зелёный.
